# Подготовка Cart для Order

Статус: реализация Cart, development. Основание: согласованный путь оформления
и запрос продолжить разработку от 2026-11-28. Связка с Order, Store и тестовым
Payment проверена локально; публичный gateway и экраны оформления не подключены.

## Граница этапа

- Добавить внутренний `cart.checkout.preview`: расчёт только выбранных строк из
  серверных проекций Cart в одном согласованном снимке PostgreSQL.
- Preview не резервирует остаток, не закрепляет строки и не создаёт заказ.
- Order сохраняет этот результат в своём draft до показа экрана оформления.
  При подтверждении Order использует сохранённую цену, а не цену из нового preview
  или тела браузерного запроса. По решению пользователя от 2026-11-28 на первом
  этапе draft не имеет срока действия.
- Добавить `cart.checkout.get` для восстановления текущего состояния подготовки.
- Сохранить prepare/complete/cancel, идемпотентность, отмену до prepare, удаление
  только выбранных строк и завершение старого checkout после закрытия owner.
- Выделить явную FSM существующих переходов. Не вводить новый workflow engine.

Вне ответственности Cart: реализация Order/Payment, публичный checkout API, экраны,
автоматическое истечение draft, резерв Cart и архивирование существующих заказов.

## Контракты

Preview: `{ownerUuid, shopUuid, cartUuid, items: [{recordUuid, quantity,
expectedItemVersion}]}`. Версия и количество должны совпадать с Cart. Пустой выбор,
дубли, отсутствующие/чужие/недоступные строки и занятые другим checkout отклоняются.
Цены и наименования приходят исключительно из серверных проекций. Денежные значения
передаются десятичными строками. Изменение проекции цены не обязано менять версию
строки Cart: зафиксированное соглашение принадлежит draft Order.

Ответ preview: `{cartUuid, ownerUuid, shop: {uuid, name}, currencyCode, items,
itemsTotal}`. Каждая строка содержит record/offer/product/variant UUID, наименования,
артикул, уточнения, изображение, количество, expectedItemVersion, unitPrice и subtotal.
Ответ — сущность, без data/meta. Никаких сумм на входе.

Get: `{ownerUuid, shopUuid, cartUuid, checkoutUuid}` →
`{checkoutUuid, cartUuid, status}`. Неизвестный checkout — 404, чужой scope не читается.
Get разрешён для закрытой корзины: завершение старого Order не зависит от сессии.

FSM: отсутствует + prepare → prepared; prepared + complete → completed;
prepared + cancel → cancelled; отсутствует + cancel → cancelled (tombstone).
Повторы не создают эффект; prepare после terminal не оживляет строки.
completed + cancel, cancelled + complete и отсутствует + complete запрещены.

Prepare обновляет доступность через владельцев и проверяет состав/версии. Он не
передаёт новую цену в Order и не заменяет сохранённое соглашение. После принятия
Order и полного резерва Store событие `order.checkout.completed` удаляет только
закреплённые строки. Cancel освобождает их при подтверждённом отказе оформления.

## Приёмка

Unit: FSM, входной контракт. PostgreSQL в случайной схеме: выбранный расчёт,
точные суммы, отсутствие эффектов preview, изменение цены после preview,
конфликт количества/версии, изоляция owner/shop, недоступные строки,
чтение состояния после потери ответа и после закрытия владельца.
Build и изолированный RMQ smoke новых команд. Пользовательская схема не мигрируется.

## Проверено

- `yarn build`: успешно.
- `yarn test --runInBand`: 49 бизнес/контрактных unit-тестов, 7 suites.
- `yarn test:integration`: 47 тестов, 4 suites, включая настоящий RabbitMQ transport.
- Preview, prepare, get, cancel, повторы и ошибки входа проверены через отдельную
  auto-delete очередь с реальными Cart providers и PostgreSQL в случайной схеме.
  Только внешние Store/Shop/Product adapters в этом тесте возвращают fixture-данные;
  полный межсервисный путь отдельно проверен скриптом workspace
  `agent/scripts/smoke-order-checkout.cjs` с настоящими Order, Store, Payment и outbox.
- Проверены чтение цен в одном снимке при конкурентной записи и сохранение ранее
  выданного расчёта после изменения проекции. Долговечное хранение расчёта в draft
  реализовано в Order и проверено сквозным smoke; Cart не хранит такой draft за него.
- DTO разнесены по отдельным файлам, денежные поля не принимаются от клиента.
- Order completion принимает decimal string версии PostgreSQL bigint без потери
  точности, сохраняя поддержку прежнего безопасного integer envelope. Это проверено
  реальным outbox Order → Cart в сквозном smoke.
- Схемы и временные consumers удаляются после проверки. Изменения не опубликованы.
